# Resume Quality Rules (distilled 2026-08-04 from r/EngineeringResumes wiki,
# Google recruiter XYZ guidance, tech-resume hiring-pipeline docs)
# Consumed by tailor.py as prompt rules. Edit freely.

BULLET FORMULA
- Every bullet: strong past-tense action verb + system built + scale + measured outcome.
  XYZ form: "Accomplished [X] as measured by [Y], by doing [Z]".
- Move metrics toward the START of the bullet when possible.
- Use digits ("8", "3x", "p99"), never spelled-out numbers.
- 1 sentence per bullet, max 2 lines. No periods at end. No personal pronouns.
- Banned verbs: utilized, helped, worked on, assisted, participated, spearheaded,
  orchestrated, leveraged, pioneered, crafted, engaged.
- Preferred verbs: built, designed, architected, implemented, reduced, cut, scaled,
  automated, optimized, shipped, drove, instrumented, refactored.

SECTION ORDER (student): Education > Work Experience > Projects > Skills.
- Order bullets and projects by relevance to THIS job; best content first.
- Recruiters read top-left first and spend <30s. Page-1 top third must carry
  the strongest signal for the specific role.

SKILLS SECTION
- Max 3 lines, comma-separated, ordered most-relevant-first FOR THIS JOB.
- Only skills the candidate could interview on. Skills used in bullets should
  appear here and vice versa.
- No soft skills, no IDEs, no "GitHub" (use "Git").

ATS / FORMATTING
- Single column, no icons/graphics/tables for content. (Our template complies.)
- Don't bold keywords inside bullets (distracting); bolding is for headers.
- En dashes for date ranges.

CONTEXT NOTES FOR THIS CANDIDATE
- GPA 4.0: always keep visible (wiki: include if >3.75).
- "U.S. Citizen" displayed in header removes sponsorship ambiguity (wiki-endorsed).
- Coursework line is low-value per wiki; MAY be dropped for space when a JD-relevant
  bullet needs room. Keep ML/DL courses when applying to ML roles.
- TartanHacks bold: keep despite no-bold rule (deliberate exception, award signal).
